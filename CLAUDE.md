# CLAUDE.md

Правила работы в этом репозитории. Читается автоматически, соблюдать без напоминаний.

## Что это

Android-приложение StreetPass: фиксация встреч с другими пользователями того же
приложения по BLE. Без GPS, без сервера, без аккаунтов. Полное ТЗ — `SPEC.md`.

## Стек и версии

Kotlin 2.0.21, AGP 8.7.2, KSP 2.0.21-1.0.28, Compose BOM 2024.10.01, Room 2.6.1,
DataStore 1.1.1. minSdk 26, targetSdk 35, compileSdk 35, JVM target 17.
Версии зафиксированы в `gradle/libs.versions.toml` — менять только по явной просьбе.

Package: `space.megaworld.streetpass`

## Команды

```bash
./gradlew assembleDebug          # сборка
./gradlew installDebug           # установка на подключённое устройство
./gradlew lint                   # обязательно перед завершением задачи
./gradlew test                   # unit-тесты
adb logcat -s DiscoveryService BleScanner BleAdvertiser IdentityKeys IdentityRepository
```

Если `gradlew` отсутствует: `gradle wrapper --gradle-version 8.9`.

**Компиляция обязательна.** Задача не считается выполненной, пока
`./gradlew assembleDebug` не проходит. Не отчитывайся об успехе по результату
чтения кода.

## Жёсткие запреты

- Никакого GPS, `ACCESS_COARSE_LOCATION`, Geofencing, Location API. На Android 12+
  `BLUETOOTH_SCAN` объявлен с `neverForLocation` — этот флаг не снимать.
- Разрешение `CAMERA` — только для сканера QR-приглашений (`ui/friends/QrScanner`),
  запрашивается на его экране; кадры не сохраняются.
- Разрешение `INTERNET` есть ради одного: проверки обновлений в
  `data/update/UpdateRepository` через GitHub Releases API, только по нажатию
  пользователя. Никакого другого сетевого кода, аналитики, телеметрии. Сетевых
  библиотек (Retrofit, OkHttp, Ktor) не подключать — `HttpURLConnection` достаточно.
- Не добавлять `BLUETOOTH_CONNECT`: оно нужно только для системного диалога
  включения Bluetooth, вместо которого открываются настройки.
- Не хранить и не логировать MAC-адреса, имена устройств, координаты.
- Не подключать DI-фреймворк (Hilt/Koin) — используется `AppContainer` в
  `StreetPassApp`. Не заводить второй способ получения зависимостей.
- Не использовать `runBlocking` в UI и в колбэках Bluetooth-стека.
- Не менять `SERVICE_UUID`, `NICKNAME_UUID`, `PROOF_UUID`, формат рекламных пакетов
  и формат доказательства в `IdentityProof` (домен подписи, раскладка байт, кривая)
  без явной просьбы: это ломает совместимость с уже установленными сборками.
- ID — производная от ключа подписи (`IdentityKeys`), не случайные байты. Не
  заводить второй источник ID и не подписывать ничего другим ключом.
- Формат приглашения в `FriendInvite` (домен подписи, раскладка) и параметр
  `#invite=` в ссылке — часть протокола, менять только по явной просьбе.
- Не переименовывать id достижений в `Achievement.ALL` — они лежат в базе.
  Достижения считаются по базе через `AchievementRepository.check`, а не по
  событиям: не заводить счётчики «в обход».

## Стиль

- Полные файлы целиком, без частичных вставок с многоточиями.
- Комментарии — на русском, только там, где объясняют **почему**, а не **что**.
  Особенно: ограничения Android, обходы багов вендоров, неочевидные лимиты API.
- Строки UI — только в ресурсах: `values/strings.xml` (английский, по умолчанию)
  и `values-ru/strings.xml`. Литералов в Compose и в сервисе не оставлять; при
  добавлении строки заполнять оба файла. Формы множественного числа — через
  `<plurals>`.
- Публичные API репозиториев — только `suspend` или `Flow`, без колбэков.
- Один экран = один файл: Composable + его ViewModel вместе.
- `Flow` в UI собирается через `collectAsStateWithLifecycle`.
- Ошибки BLE не глотать молча: класть в `DiscoveryState.error` и показывать.
- Любой вызов BLE API оборачивать в try/catch на `SecurityException` и
  `IllegalStateException` — разрешение может быть отозвано в рантайме, адаптер
  может выключиться между проверкой и вызовом.

## Проверка после изменений в BLE или сервисе

1. `./gradlew assembleDebug lint`
2. Сборка ставится на устройство и не падает при старте.
3. Тумблер обнаружения включается, уведомление появляется.
4. `adb logcat` не сыплет `SecurityException` и `SCAN_FAILED_*`.

Эмулятор BLE не поддерживает — проверка только на физическом устройстве.
Если устройства нет, честно скажи, что проверил только компиляцию.
